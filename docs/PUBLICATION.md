# Состав и происхождение репозитория

Публичный репозиторий проекта — [YARzich/franka_pick_and_place](https://github.com/YARzich/franka_pick_and_place).
Его начальный коммит содержит проверенную версию семи пакетов ROS 2.
Исходный `ros2_examples` сохраняет прежнюю историю разработки.

## Состав

В новом корне находятся семь каталогов ROS-пакетов, `scripts`, `training`, документация,
`LICENSE`, `THIRD_PARTY_NOTICES.md`, `.gitignore`, `CPPLINT.cfg`, `AGENTS.md` и
проектные tools в `.agents/skills/{validate-franka-manipulation,diagnose-franka-perception}`.
Проверки запускаются локально по INSTALL. GitHub Actions исключён из текущей
поставки по решению владельца.

Переносится проверенный список исходников, а не рекурсивная копия рабочего
каталога: исключаются Git-история, build/install/log, кеши, локальные настройки
Claude/IDE и соседние проекты. Изменения вне семейства относятся к публикации
только когда это явно перечисленные policies и tools. Отдельный
`training/` содержит проверенную копию нужных инструментов из
`perception_training`; исходный соседний проект целиком не переносится.

Веса моделей остаются вместе с относящимися к ним лицензиями и уведомлениями:
на них опираются существующие сценарии. Выбор Git LFS или release assets
не должен молча ломать default model paths. Текущие файлы меньше лимита
одного обычного Git blob; исторические версии при новой истории не переносятся.

## Модели и атрибуция

1. [YOLO checkpoints](../franka_motion/models/THIRD_PARTY_NOTICES.md) имеют
   AGPL-3.0 metadata. Настройки всех шести обучений и состав dataset manifests
   сохранены в [комплекте обучения](../training/README.md) вместе с исходниками
   подготовки данных и дообучения. Он включает происхождение, hashes,
   переносимые пути и проверку рецептов без запуска обучения.
   Исходники приложения, инструкции и ссылка на Ultralytics 8.4.19 доступны в
   том же исходном дереве. Для приложения с YOLO применяются условия AGPL;
   MIT отдельных самостоятельных файлов не отменяет их. Отдельные бинарные
   поставки должны сопровождаться соответствующей версией исходников.
   Приложение использует готовые веса. Повторное обучение, восстановление
   исторических запусков и подготовка датасетов не входят в эту задачу.
   Training-исходники сопровождают модели и не запускаются при сборке.
2. [MoveIt-конфигурация](../franka_motion/config/moveit/THIRD_PARTY_NOTICES.md)
   закреплена по версии 3.1.0 и commit. Сохранены автор, история источника,
   сведения о местных изменениях, три условия BSD и disclaimer. Основание
   BSD-3-Clause — официальная документация MoveIt, включающая
   `moveit_resources`; package.xml сохраняет исходное обозначение `BSD`.
   Несуществующий upstream LICENSE или неизвестные copyright-даты не
   выдумываются. Отсутствие отдельного LICENSE у исходного пакета описано
   как ограничение детализации атрибуции.

## Проверка комплекта

Технические и организационные проверки:

- Сборка и пакетные тесты из отдельной копии исходников без рабочего overlay.
- Source architecture checks и проверки переносимости диагностических tools.
- Проверка состава, размеров, явных секретов и сохранности license notices.
- Адрес сопровождающего `yaric002@gmail.com` подтверждён владельцем и указан
  в package.xml всех семи пакетов.
- Лицензионные notices соответствуют закреплённым версиям и отделяют
  подтверждённое происхождение от неизвестных деталей.
- Приватные сообщения об уязвимостях принимаются на подтверждённый email по
  [SECURITY.md](../SECURITY.md). Дополнительно можно включить private reporting
  на GitHub; основной способ связи не зависит от этой настройки.

Проверки комплекта не являются сертификацией будущего развёртывания: условия
отдельно выбранных backends и способ распространения должны соответствовать
их лицензиям.

Исторические `/tmp/...` в ROADMAP — ссылки на локальные прогоны разработки,
а не доступные пользователю артефакты или воспроизводимая установка. Для нового
checkout применяются INSTALL и тесты; старые прогоны не подменяют новую приёмку.

Отдельный репозиторий сохраняет уровень доверия `candidate`. Публикация
исходников не заменяет runtime-проверки и не повышает этот уровень.
